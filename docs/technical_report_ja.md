# 単眼カメラによるフィギュアスケート3D軌道復元: 技術レポート

**バージョン:** 5.0
**日付:** 2026-06-02
**著者:** 鶴羽 佳秀 (Yoshihide Tsuruha)

---

## 概要

フィギュアスケートのジャンプ定量分析は、従来は高価なマルチカメラモーションキャプチャーシステムやウェアラブルセンサーを必要としてきた。本文書は、Ice Coachが実装する技術的アプローチを記述する。本システムは単眼スマートフォンカメラから3D軌道復元および回転不足の自動判定を行う — キャリブレーション不要、リンク基準点不要、ウェアラブルセンサー不要。

核となるのは**2D → 3D → 解析 → 2Dパイプライン**である。2D動画フレームをまずMediaPipeのWorld Landmark Modelにより3Dモーションキャプチャーデータに変換し、ジャンプ指標と回転不足を3D世界座標上で算出し、結果を元の動画上にオーバーレイとして投影する。このアプローチにより、2D画像解析のみでは得られない計測精度を実現する。

回転不足検出手法は、MoCap由来の肩方向を用いた安定角度平均化とチェックアウトオフセット補正を組み合わせたアプローチである。

---

## 1. 設計思想

Ice Coachは以下の制約のもとで3D軌道復元を実現する:

- **カメラキャリブレーション不要**: スマートフォンで撮影した動画をそのまま処理
- **リンク基準点不要**: リンク上の既知座標点を使用しない
- **クライアントサイド処理**: ブラウザ上で完結し、サーバーを必要としない

## 2. コアパイプライン: 2D → 3D → 解析 → 2D

Ice Coachは2D動画を直接解析するのではなく、以下のパイプラインで処理する:

1. **2D → 3D復元**: MediaPipe PoseLandmarkerが各フレームから2D画面座標と3D World Landmarks (WLM)を同時に出力する。WLMデータ（カメラ空間でのルート相対3D関節位置）は、フレーム間の腰変位を追跡することで世界座標に変換され、モーションキャプチャー（MoCap）データとなる。

2. **3Dで解析**: ジャンプ軌跡・高さ・回転不足・バイオメカニクス等の全定量計測は、3D世界座標のMoCapデータから算出する。

3. **3D → 2D投影**: 解析結果はcanvasオーバーレイとして元の2D動画上にフレーム同期で投影する。

```
入力: 単眼カメラ動画 + スケーターの身長
       |
       v
[A] 骨格推定 (MediaPipe PoseLandmarker)
       |  2Dキーポイント + 3D World Landmarks (WLM)、GPU加速
       |
       +--> [B] MoCap復元 (WLM → 世界座標)
       |         → フレームごとの3D関節位置
       |
       +--> [C] ジャンプ検出（重心解析）
       |
       +--> [D] 奥行き推定（骨格の画素サイズ）
       |
       +--> [E] 3D位置復元（ピンホールカメラモデル）
       |
       +--> [F] 回転不足検出（3D肩方向計測）
       |
       +--> [G] 軌跡描画・オーバーレイ
       |
       v
出力: 3D軌跡 + 骨格オーバーレイ + 回転不足判定
```

## 2.1 MoCap復元

MediaPipeのWorld Landmark Modelは各関節のルート相対3D座標（X: 横方向、Y: 垂直、Z: カメラ奥行き）を出力する。これを以下の手順で世界座標に変換する:

1. **ルート追跡**: 骨盤中点（LeftHipとRightHipの平均）の2D画面座標をフレーム間で追跡。画面上の移動量をスケーリングして世界座標の移動量に変換。
2. **関節配置**: 各関節のWLMルート相対オフセットを身長でスケーリングし、世界座標のルート位置に加算。
3. **地面校正**: 最も低い足の位置が氷面（Y=0）に対応するよう垂直軸を調整。

これにより、バイオメカニクス解析に適した世界座標系のフレームごとMoCapデータが得られる。

## 3. 骨格推定

MediaPipe PoseLandmarker（heavyモデル、float16）がGPU加速（WebGL）推論により各フレームから33の身体キーポイントを検出する。モデルは以下を同時に出力する:

- **2Dランドマーク**: 各関節の正規化画面座標 (x, y)
- **3D World Landmarks (WLM)**: カメラ空間でのルート相対3D座標 (x, y, z)

デバイスによらず60fpsで処理する。複数人が映っている場合、IoUベースのバウンディングボックストラッキングで対象スケーターをフレーム間で追跡し、IDスイッチを防止する。

## 4. ジャンプ検出

ジャンプは重心（CoG: 肩中点と腰中点の中間点）の垂直位置から検出する。

1. **垂直信号の抽出**: 各フレームのCoG Y座標を抽出し、ノイズ除去のため平滑化。
2. **ピーク検出**: 垂直信号の局所最小値（身体が最高到達点に達した点）を、スケーティング動作と区別するのに十分な突出度で検出。
3. **離氷検出**: ピークから後方にスキャンし、CoGが上昇を開始するフレームを離氷と特定。
4. **着氷検出**: ピークから前方にスキャンし、CoGが離氷前の垂直レベルに戻るフレームを着氷と特定。
5. **滞空時間計測**: 離氷〜着氷のフレーム間の時間が滞空時間Tとなり、ここからジャンプの高さを算出。

## 5. 氷面射影

足首の2D画面座標を、レイと氷面平面の交差により氷面上に投影する。正規化画面座標 `(u, v)` と仮定されたカメラパラメータ（高さ、チルト角、焦点距離）から:

```
ray_direction = (u/f, -(v/f × cos(tilt) - sin(tilt)), v/f × sin(tilt) + cos(tilt))
t = -camera_height / ray_y
ice_position = t × (ray_x, ray_z)
```

フレーム間の氷面上の変位は数値微分（ヤコビアン）で算出する:

```
dz/dv ≈ (z(v + ε) - z(v - ε)) / (2ε)
```

これにより3Dリンクビューで使用される氷面上の軌跡が得られる。

## 6. 奥行き推定

ピンホールカメラモデルを用いて、骨格の見かけの画素サイズからカメラ〜スケーター間の距離を推定する:

```
Z = L_real × f / L_observed
```

ここで:
- `L_real`: 既知の身体部位の実寸（入力された身長と解剖学的比率から導出）[m]
- `f`: 焦点距離（標準的なスマートフォンの画角から推定）[px]
- `L_observed`: 現在のフレームにおける身体部位の画素長 [px]

観測された身体部位の長さは、回転による短縮のアーティファクトを除去するため、中央値フィルタで前処理される。

## 7. 3D位置復元

2D画面位置と推定された奥行きからワールド座標を復元する:

```
X = (u - u₀) × Z / f
Y = (v - v₀) × Z / f
```

ここで `(u, v)` は画面位置、`(u₀, v₀)` は主点（画像中心）。標準的なピンホールカメラの逆投影である。

## 8. 高さ算出

ジャンプの高さは自由落下の物理公式から滞空時間のみで決定する:

```
H = g × T² / 8
```

ここで `g` は重力加速度、`T` は計測された滞空時間。

## 9. 後処理

1. **中央値フィルタ**: 回転時の身体計測値のスパイクノイズを除去
2. **ガウシアン平滑化**: 接地中の氷上座標のフレーム間ジッターを低減
3. **曲率制約**: スケーティングの物理に基づく最小旋回半径を適用
4. **速度クランプ**: 物理的に妥当な範囲の最大速度・最大加速度を制限

## 10. 軌跡描画

ブレード接地点をフレームごとに追跡し、以下の処理を経て描画する:
1. スパイク除去のための中央値フィルタ
2. ノイズ低減のための移動平均
3. 滑らかな曲線描画のためのスプライン補間

描画された軌跡は動画上に合成され、動画フレームと同期して表示される。

## 11. スケール校正

セグメンテーションモデルがスケーターの身体領域を検出する。入力された身長と組み合わせることで、ピクセルとメートルの変換係数を得る。

## 12. 遮蔽への対応

- 骨格推定が失敗したフレームは無効としてスキップ
- 有効フレーム間は補間で軌跡を接続
- ジャンプ区間が検出された場合、氷上位置の推定は適切に調整

## 13. 回転不足(アンダーローテーション)検出

### 13.1 概要

回転不足検出は、ジャンプ着氷時の回転不足角度を定量化する。ISU（国際スケート連盟）のジャッジは目視で回転不足を評価するが、標準化された計算手法は公開されていない。Ice Coachは、MoCapベースの体の向き計測による新しい自動化アプローチを導入する。

### 13.2 手法

3Dモーションキャプチャ（MoCap）による骨格再構成から、XZ平面（氷面）上の肩の向きを計測する。

**ステップ1: 体の向き角度**

肩ライン（LeftShoulder → RightShoulder）の法線をMoCap世界座標系のXZ平面に投影して体の向きを算出する:

```
dx = RightShoulder.x - LeftShoulder.x
dz = RightShoulder.z - LeftShoulder.z
facing_angle = atan2(dx, -dz)
```

3D空間での回転を捉えるため、体がカメラに正対/背面を向いた際に2D肩角度で生じる±180°フリップのアーティファクトを回避できる。

**ステップ2: 安定角度（基準方向）**

着氷後にスケーターが安定した方向を向いた時の角度を、着氷後の短い時間窓における体の向き角度の**平均**として算出する:

```
settled_angle = mean(facing_angle[t_land + t_start ... t_land + t_end])
```

複数フレームの平均をとることで、GPUベースの姿勢推定に内在する非決定性を吸収する。

平均化の前に角度のアンラップ処理を行い、±180°境界を正しく処理する。

**ステップ3: 不足角度の算出**

生の不足角度は、着氷時の体の向きと安定角度の角度差である:

```
raw_deficit = |angle_diff(facing_at_landing, settled_angle)|
```

**チェックアウトオフセット**を差し引く。これはブレードのロッカーカーブ上での正常な着氷後回転であり、ISUジャッジも回転不足とは見なさない:

```
deficit = max(0, raw_deficit - checkout_offset)
```

**ステップ4: ISU基準による分類**

| 記号 | 不足角度範囲 | GOE影響 |
|------|------------|---------|
| OK | 45°未満 | なし |
| q | 45° 〜 89° | GOE -1 |
| < | 90° 〜 179° | GOE -2〜-3, 基礎点×0.80 |
| << | 180°以上 | GOE -3〜-4, 基礎点1回転下 |

### 13.3 設計上の判断

| 課題 | 解決策 |
|------|--------|
| 2Dのheel-toeランドマークがノイズ大（数ピクセル差） | MoCap 3D肩方向を代わりに使用 |
| 2D肩角度が回転中に±180°でフリップ | MoCap世界座標（XZ平面）を使用 |
| MoCap腰ラインのカメラパースドリフト | 肩ライン使用（滑走中はより安定） |
| GPU推論の非決定性 | 時間窓でsettled角度を平均化 |
| 正常な着氷後回転が不足として計測される | チェックアウトオフセットを差し引き |
| PC/スマホの精度不一致 | heavyモデル+60fpsを全デバイスで統一 |

### 13.4 制約

- MoCapの肩位置の精度に依存する。体がカメラに正対/背面を向くと精度が低下する
- チェックアウトオフセットは経験的に決定された値であり、ジャンプの種類やスケーターにより異なる可能性がある
- ISUジャッジは着氷時のブレードの向きを評価するが、本手法は体（肩）の向きを代理指標として使用している
- 動画デコードとGPU推論の非決定性により、解析結果は実行ごとに±5°程度変動しうる

## 14. 関連研究

### フィギュアスケートのモーション解析

フィギュアスケート解析の先行研究は、主にViconやOptiTrackなどのラボ用モーションキャプチャーシステムに依存してきた。これらは高精度だが、管理された環境と反射マーカーを必要とし、日常的なコーチングには不向きである。

### 単眼3D姿勢推定

単眼カメラからの3D姿勢推定（MediaPipe、OpenPose、MMPose等）の進歩により、単一カメラからの骨格検出が可能になった。しかし多くの応用は姿勢認識やアクション分類に焦点を当てており、定量的なバイオメカニクス計測には至っていない。

### 回転不足の評価

ISUのテクニカルパネルはスロー再生による目視判定で回転不足を評価する。標準化された計算手法は公開されていない。Ice Coachは単眼カメラ映像から着氷時の回転不足を自動定量化するアプローチを提供する。

### 本研究の位置づけ

Ice Coachは、ラボ用モーションキャプチャーと実用的なコーチングツールの間のギャップを以下により埋める:
- 専用機器ではなく一般的なスマートフォンを使用
- サーバー依存なしに完全クライアントサイド（ブラウザ）で処理
- 2D観測を3D MoCapデータに変換して解析し、結果を2Dに投影
